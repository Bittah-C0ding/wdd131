Study Planner Site Plan

Adrian Hernandez

WDD 131 – Dynamic Web Fundamentals

Overview

Purpose

The Study Planner is a task management tool designed for university students. It helps users organize assignments, track deadlines, and manage study tasks by course and priority. The app provides a clear dashboard with statistics, filtering and sorting options, and a calendar view to visualize upcoming due dates. The goal is to reduce academic stress and improve time management.

Audience

This app is intended for college and university students who need a simple, effective way to track their coursework. The target audience includes students managing multiple classes, assignments, and deadlines. The app works on all devices – phone, tablet, and desktop – so students can update their tasks anywhere, anytime.

Dynamic Elements

JavaScript will be used to make the Study Planner interactive and functional. The following dynamic features will be implemented:

  • Objects & Arrays: Tasks will be stored as an array of objects. Each task object will have properties: id, title, course, dueDate, priority (high/medium/low), notes, and completed (boolean).
  • Array Methods:
    • .forEach() – Render each task card to the DOM.
    • .filter() – Filter tasks by status (active/completed), priority, and course.
    • .sort() – Sort tasks by due date, priority, or title.
    • .reduce() – Calculate average priority and total task counts for dashboard statistics.
  • DOM Interaction:
    • Select elements using document.querySelector and getElementById.
    • Modify the DOM by rendering task cards dynamically when tasks are added, deleted, or updated.
    • Listen for and react to events: click (add/delete/toggle tasks), change (filter/sort dropdowns), submit (add task form).
  • Conditional Branching:
    • Check if tasks are overdue by comparing due dates to today's date.
    • Validate form inputs (e.g., title and due date are required).
    • Show/hide the add task page based on navigation.
    • Display messages when no tasks match the current filters.
  • Local Storage: Tasks will be saved in the browser's localStorage so that data persists between sessions.

Pseudocode – Computational Thinking

1. Define an array `tasks` to store task objects.
2. Define a counter `nextId` to assign unique IDs.
3. Create a `saveTasks()` function to store `tasks` in localStorage.
4. Create a `loadTasks()` function to retrieve tasks from localStorage on page load.
5. Create `renderTasks()` function:
   a. Get values from filter dropdowns (status, priority, course) and sort dropdown.
   b. Use `.filter()` to create a filtered array based on selected criteria.
   c. Use `.sort()` to sort the filtered array.
   d. If no tasks match, display a "no tasks" message.
   e. Otherwise, use `.forEach()` to generate HTML for each task card and insert into the DOM.
   f. Update dashboard statistics.
   g. Reattach event listeners to delete and toggle buttons.
6. Create `updateStats()` function:
   a. Use `.reduce()` to calculate total, completed, overdue, and average priority.
   b. Update the stat cards in the dashboard.
7. Create `addTask(taskData)` function:
   a. Create a new task object with id, title, course, dueDate, priority, notes, completed: false.
   b. Push to `tasks` array.
   c. Save to localStorage.
   d. Re-render tasks.
8. Create `deleteTask(id)` function:
   a. Use `.filter()` to remove the task with the matching id.
   b. Save to localStorage.
   c. Re-render tasks.
9. Create `toggleComplete(id)` function:
   a. Use `.find()` to locate the task with the matching id.
   b. Toggle the `completed` property.
   c. Save to localStorage.
   d. Re-render tasks.
10. Create `renderCalendar()` function:
    a. Get the current month/year.
    b. Loop through each day of the month.
    c. Count tasks due on each day using `.filter()`.
    d. Render a calendar grid with task indicators.
11. Attach event listeners:
    a. Tab navigation: switch between Dashboard, Add Task, and Calendar views.
    b. Add Task button → show the Add Task page.
    c. Task form submit → call `addTask()`.
    d. Filter/sort dropdowns → call `renderTasks()`.
    e. Delete button on each card → call `deleteTask()`.
    f. Toggle complete button on each card → call `toggleComplete()`.
12. On page load:
    a. Call `loadTasks()` to retrieve tasks.
    b. Call `renderTasks()` to display tasks.
    c. Call `renderCalendar()` to display the calendar.
    d. Populate the course filter dropdown with unique course names.
